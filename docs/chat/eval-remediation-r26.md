# Evidence-bound read workflows

The planned executor can discover a compact manager overview, load the exact
observed field and input types, and query the requested population. These steps
use the same exposure-filtered GraphQL contract and manager snapshot. A changed
snapshot requires a new overview and matching details. Legacy schema requirements
without an explicit view continue to require the full schema.

For independent reads, the executor may issue several tool calls in one provider
round after each call's schema and identity prerequisites have been satisfied.
Tools still execute in their declared order. A call cannot use a result that has
not yet been returned to the executor.

Natural-language categories need actual exposed field values. A record's name is
not necessarily its family or enum value. The category lookup and binding
workflow validates a complete unfiltered lookup, exact typed values, current
schema and generated filter semantics. An empty query for an unverified label
does not establish global absence. Ordinary exact user-supplied filters remain
available. Unsupported custom filter semantics do not acquire proof authority
from an input field's spelling.

Proof authority follows the common executable contract: the exact list resolver,
inherited manager entry points, generated input containers, field mappings,
defaults, scalar and enum coercion, shared relation normalization, and the actual
output getter and manager attribute source. Copied
resolver attributes or wrappers do not establish that authority. Changes to
these bindings invalidate the exposed proof metadata and existing query
witnesses. An unsupported binding can still serve an ordinary query, but cannot
certify the new category or cross-query workflows. Relation predicates must
retain the same manager namespace at each hop. These checks use the shared
manager interface rather than backend-specific ORM assumptions.

The generated normal getter attests an identity source only with its exact
`authorize_manager_collection=False` mode. Its field name and disabled member
filter are captured together and remain bound to the generated code, defaults,
and shared permission helpers. Other modes, including non-boolean false-like
values, do not acquire this proof. Native manager collections keep their own
GraphQL member permission filtering and do not claim unchanged attribute
identity. Changing a getter capture revokes its certificate and existing schema
and query witnesses. Measurement getter certificates retain their separate
conversion contract.

Arithmetic over different queries uses an explicit, narrow contract described in
[cross-query calculations](cross-query-calculations.md). It preserves both source
populations and proves their entity, period, executable unit declaration and
query-time schema witnesses. Missing unit metadata is not permission to assume a
unit. The existing checks remain in force for ordinary calculation bindings.

For complete grouped sums, [calculate_groups](complete-group-calculations.md)
derives each group's exact operand paths from explicitly selected complete query
evidence. All calculations must pass the existing validators before any group
is committed. A queried calculation-manager scalar needs another aggregate only
when the declared requirement requires it. Already computed values do not replace
the requested historical basis or proof of complete training years.

The final answer should cover the user's requested components and distinguish
actual observations, existing plans, new forecasts and recommendations. Applicable
configured definitions resolve choices within their scope. They do not establish
record values or authorize extra filters. The current conditional rules for
supplier approval and WBS breakdowns remain conditional; this change introduces
no universal business defaults or required regression disclosure checklist.

[Reference transport](reference-transport-r26.md) changes request representation
without changing logical evidence. Schema-only codecs retain their separate
roundtrip checks. Selecting exact definitions for a particular task does not
prove a full-schema roundtrip. Historical source coordinates, snapshots and
evidence links remain independent even when identical schema values share
storage.

The Eval Judge now explicitly recognizes actually incurred net project costs and
preserves the complete typed identities, component scopes and flat multi-value
constraint claims. A representable claim can still be incorrect. No omitted
numeric answer is supplied from tools, and the deterministic scorer and Gold
catalog remain unchanged.

Offline regressions establish these contracts; they do not establish model
compliance, wholecase success or faster live responses. Those claims require
separate version-bound measurements under the existing context and time limits.
